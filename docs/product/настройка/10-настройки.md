# Файл настроек (autumn-properties.json)

vanessa-runner использует файл `autumn-properties.json` для задания настроек по умолчанию на уровне проекта.

## Расположение файла

Файл `autumn-properties.json` должен находиться в рабочем каталоге, из которого запускается `vrunner`. Как правило, это корень проекта.

## Формат файла

```json
{
  "vrunner": {
    "<опция>": "<значение>",
    "<команда>": {
      "<опция>": "<значение>"
    }
  }
}
```

Ключи задаются через пространство имён `vrunner`.

## Каскад приоритетов

Настройки применяются в следующем порядке (от низшего приоритета к высшему):

1. Значения по умолчанию из пакета vanessa-runner
2. `autumn-properties.json` в текущем рабочем каталоге
3. Переменные окружения
4. Файл настроек из опции `settings`
5. Аргументы командной строки

## Опция settings

`settings` - глобальная опция, доступная всем командам. Задаётся она так же, как любая другая опция: в командной строке (`--settings <файл>` или `--settings=<файл>`), переменной окружения `VRUNNER_SETTINGS` или ключом `settings` в файле настроек. Её значение - путь к ещё одному файлу того же формата, что и `autumn-properties.json`; этот файл накладывается поверх уровней 1-3. Относительный путь считается от рабочего каталога.

Файл, заданный в командной строке или переменной окружения, обязан существовать: иначе команда завершается ошибкой `Файл настроек не найден`. Файл из ключа `settings` необязателен: если его нет, действуют настройки уровней 1-3, а причина видна в отладочном логе (`DEBUG`).

### Локальные настройки разработчика

Типичное применение опции - личные настройки поверх проектных. `autumn-properties.json` лежит в репозитории и одинаков у всех, а строка подключения к базе, версия платформы, пути к EDT и Vanessa у каждого разработчика свои. Проектный файл ключом `settings` указывает на локальный файл, который в репозиторий не попадает:

```json
{
  "vrunner": {
    "settings": "autumn-properties.local.json",
    "v8version": "8.3.24",
    "cf": {
      "compile": {
        "src": "./src",
        "out": "./build/1Cv8.cf"
      }
    }
  }
}
```

Локальный файл содержит только личные значения:

```json
{
  "vrunner": {
    "ibconnection": "/FD:/bases/MyProject",
    "v8version": "8.3.25"
  }
}
```

Команда запуска одинакова у всех разработчиков и в CI: `vrunner cf compile` берёт `src` и `out` из проектного файла, а `ibconnection` и `v8version` из локального. Там, где локального файла нет, работают проектные значения.

Чтобы локальный файл не попал в коммит, добавьте его в `.gitignore`:

```gitignore
autumn-properties.local.json
```

Удобно держать в репозитории шаблон `autumn-properties.local.json.example` с личными ключами: новый разработчик копирует его под настоящим именем и вписывает свои значения.

## Примеры конфигурации

### Базовые настройки подключения

```json
{
  "vrunner": {
    "ibconnection": "/FD:/bases/MyProject",
    "db-user": "Администратор",
    "db-pwd": "",
    "v8version": "8.3.24"
  }
}
```

### Настройки для конкретных команд

```json
{
  "vrunner": {
    "ibconnection": "/F./ib",
    "v8version": "8.3.24",
    "cf": {
      "compile": {
        "src": "./src"
      }
    },
    "repo": {
      "load": {
        "storage-name": "D:/repos/MyProject",
        "storage-user": "StorageUser"
      }
    }
  }
}
```

### Позиционные аргументы

Позиционные аргументы команд (`OUT`, `SRC`, `IN`, `TESTSPATH`) задаются в файле так же, как опции: ключом служит имя аргумента в нижнем регистре. Значение из командной строки или переменной окружения имеет приоритет над файлом. Если обязательный аргумент не задан ни одним способом, команда завершается ошибкой и подсказывает ключ настройки.

```json
{
  "vrunner": {
    "cf": {
      "compile": {
        "out": "./build/1Cv8.cf"
      }
    },
    "test": {
      "xunit": {
        "testspath": "./tests"
      }
    }
  }
}
```

С таким файлом `vrunner cf compile` и `vrunner test xunit` запускаются без аргументов.

### Пример для CI-окружения

```json
{
  "vrunner": {
    "v8version": "8.3.24",
    "ibcmd": true,
    "test": {
      "xunit": {
        "reportsxunit": "jUnit{./build/reports/junit.xml}"
      }
    }
  }
}
```

## Логирование

### Потоки вывода

По умолчанию лог (`ИНФОРМАЦИЯ - ...`, `ОШИБКА - ...`) и данные команд идут в stdout, как в vanessa-runner 2.x. Ключ `log-output` переводит лог в stderr, тогда в stdout остаются только данные команд: JSON, таблицы, списки, и их можно разбирать, не вычищая строки лога:

```json
{
  "vrunner": {
    "log-output": "stderr"
  }
}
```

```bash
vrunner infobase extensions list --json --ibconnection /F./ib | jq '.[].имя'
```

Значения: `stdout` (по умолчанию) и `stderr`. Для разового запуска ключ задаётся переменной окружения `VRUNNER_LOG_OUTPUT`, она сильнее файла настроек.

В терминале и в логе CI при `stderr` оба потока видны вместе. Отличие проявляется при перенаправлении: `vrunner ... > out.txt` сохраняет только данные, лог остаётся на экране. Чтобы сохранить в файл и лог, перенаправьте оба потока: `vrunner ... > out.txt 2>&1`.

### Уровни

Уровень логирования настраивается через `autumn-properties.json`:

```json
{
  "logos": {
    "logger": {
      "vrunner": "DEBUG"
    }
  }
}
```

Доступные уровни: `DEBUG`, `INFO`, `WARN`, `ERROR`.

Или через переменную окружения:

```bash
export LOGOS_LOGGER_VRUNNER=DEBUG
vrunner cf compile ./build/App.cf
```
