# run - Запуск 1С

Запуск 1С:Предприятия или Конфигуратора с нужными параметрами из командной строки. Это интерактивные команды, в [MCP](../mcp) они не выставляются.

```bash
vrunner run <подкоманда> [опции]
```

## enterprise

Запускает 1С:Предприятие (тонкий клиент, толстый - при `--ordinaryapp`) и по умолчанию ждёт его завершения.

```bash
vrunner run enterprise [опции]
```

### Опции

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--command` | `VRUNNER_COMMAND` | Строка, передаваемая в параметр запуска `/C` |
| `--execute` | `VRUNNER_EXECUTE` | Путь к внешней обработке для запуска (`/Execute`); поддерживается макрос `$runnerRoot` |
| `--url` | - | Навигационная ссылка для перехода после старта (`/URL`) |
| `--no-wait` | - | Не ожидать завершения 1С:Предприятия |
| `--exitCodePath` | - | Путь к файлу статуса выполнения: `0` - успех, `1` - ошибка, `2` - предупреждение |

> Общие опции: [подключение к ИБ](./common-options#подключение-к-информационной-базе), [платформа](./common-options#платформа), [запуск клиента](./common-options#запуск-клиента), [файл настроек](./common-options#файл-настроек).

Запуск через автономный сервер (`--ibsrv`) работает только с файловой ИБ и несовместим с `--no-wait` - в обоих случаях режим ibsrv игнорируется с предупреждением.

### Файл статуса (--exitCodePath)

Путь передаётся обработке в строке `/C` как `exitCodePath=<путь>` (через `;` после значения `--command`; если в `--command` уже есть `exitCodePath=` или `xddExitCodePath`, повторно не добавляется). После завершения 1С:Предприятия vrunner читает файл: `0` - успех, `2` - предупреждение в логе, `1` и любое другое значение - команда завершается ошибкой. Если обработка файл не создала, выводится предупреждение, команда считается успешной. С `--no-wait` файл не читается.

### Макрос $runnerRoot

В `--execute` макрос `$runnerRoot` раскрывается в каталог установки vanessa-runner - так запускаются обработки из его поставки (каталог `epf`). Файл обработки должен существовать, иначе команда завершается ошибкой.

### Примеры

```bash
# Запустить обработку и проверить результат по файлу статуса
vrunner run enterprise \
  --ibconnection /F./ib \
  --execute ./tools/InitIB.epf \
  --exitCodePath ./build/result.txt

# Передать параметр запуска /C
vrunner run enterprise \
  --ibconnection /F./ib \
  --command "StartFilling" \
  --v8version 8.3.24

# Обработка из поставки vanessa-runner
vrunner run enterprise \
  --ibconnection /F./ib \
  --execute '$runnerRoot/epf/ЗакрытьПредприятие.epf'

# Открыть навигационную ссылку и не ждать закрытия клиента
vrunner run enterprise \
  --ibconnection /F./ib \
  --url "e1cib/list/Catalog.Контрагенты" \
  --no-wait
```

## designer

Запускает Конфигуратор и по умолчанию ждёт его закрытия. Если задан `--storage-name`, Конфигуратор открывается с подключением к хранилищу (`--storage-user`, `--storage-pwd`; `--storage-ver` не используется).

```bash
vrunner run designer [опции]
```

### Опции

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--additional` | `VRUNNER_ADDITIONAL` | Дополнительные параметры запуска Конфигуратора |
| `--no-wait` | - | Не ожидать закрытия Конфигуратора |

> Общие опции: [подключение к ИБ](./common-options#подключение-к-информационной-базе), [платформа](./common-options#платформа), [хранилище конфигурации](./common-options#хранилище-конфигурации), [файл настроек](./common-options#файл-настроек).

### Примеры

```bash
# Запустить Конфигуратор с дополнительными ключами
vrunner run designer \
  --ibconnection /F./ib \
  --additional "/DumpConfigToFiles ./src"

# Открыть Конфигуратор с подключением к хранилищу и не ждать закрытия
vrunner run designer \
  --ibconnection /F./ib \
  --storage-name D:/repos/MyProject \
  --storage-user Администратор \
  --no-wait
```
