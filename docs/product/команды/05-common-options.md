# Общие опции

Наборы опций, которые повторяются у многих команд, описаны здесь один раз. На странице команды под таблицей её собственных опций перечислены наборы, которые у неё есть, со ссылками на разделы этой страницы.

## Подключение к информационной базе

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--ibconnection` | `VRUNNER_IBCONNECTION` | Строка подключения: `/F<путь>` - файловая ИБ, `/S<сервер>\<база>` - серверная |
| `--db-user` | `VRUNNER_DBUSER` | Пользователь информационной базы (не ОС и не СУБД) |
| `--db-pwd` | `VRUNNER_DBPWD` | Пароль пользователя ИБ |

Примеры: `--ibconnection /F./ib`, `--ibconnection /FD:/bases/MyProject`, `--ibconnection "/SMyServer\MyInfobase"`.
Если база не требует аутентификации, `--db-user` и `--db-pwd` можно не указывать.

### Когда база необязательна

| Команды | Поведение без `--ibconnection` |
|---------|-------------------------------|
| `cf compile`, `cf decompile`, `cfe compile`, `cfe decompile`, `epf compile`, `epf decompile`; `cf compare`, `cfe compare` при сравнении двух файлов | Создаётся временная файловая ИБ, после операции удаляется |
| `infobase init` | Создаётся файловая ИБ `build/ib` (не удаляется) |
| `infobase update`, `infobase create-user`, `infobase lock-resources`, `infobase extensions *`, `infobase scheduled-job *`, `cfe load`, `cfe unload` | Используется файловая ИБ `build/ib` - та, которую создаёт `infobase init` |
| Остальные команды | База обязательна: укажите `--ibconnection` |

## Конфигуратор или ibcmd

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--ibcmd` | - | Использовать утилиту `ibcmd` вместо Конфигуратора |

По умолчанию операции с конфигурацией выполняет Конфигуратор (`1cv8 DESIGNER`). `ibcmd` работает с базой напрямую, без запуска клиента и кластера серверов. Опция есть только у команд, которые умеют работать обоими способами.

| | Конфигуратор | ibcmd |
|---|---|---|
| Кластер серверов для серверной ИБ | Нужен | Не нужен |
| Опции СУБД для серверной ИБ | Не нужны | Нужны |
| `--rtype`, `--dynamic` | Поддерживаются | Игнорируются |

## Опции СУБД

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--dbms-type` | `VRUNNER_DBMS_TYPE` | Тип СУБД: `MSSQLServer`, `PostgreSQL`, `IBMDB2`, `OracleDatabase` |
| `--dbms-server` | `VRUNNER_DBMS_SERVER` | Адрес сервера СУБД |
| `--dbms-base` | `VRUNNER_DBMS_BASE` | Имя базы данных СУБД |
| `--dbms-user` | `VRUNNER_DBMS_USER` | Пользователь СУБД |
| `--dbms-pwd` | `VRUNNER_DBMS_PWD` | Пароль СУБД |

Нужны в одном случае: **`--ibcmd` + серверная ИБ** - `ibcmd` подключается к СУБД напрямую, минуя сервер 1С. Опции применяются только при заданном `--dbms-type`. Для файловых баз и при работе через Конфигуратор не нужны.

## Платформа

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--v8version` | `VRUNNER_V8VERSION` | Версия платформы 1С (по умолчанию - старшая установленная) |
| `--uccode` | `VRUNNER_UCCODE` | Код разрешения для входа в заблокированную базу (`/UC`) |
| `--language` | `VRUNNER_LANGUAGE` | Язык интерфейса платформы (`/L`) |
| `--locale` | `VRUNNER_LOCALE` | Язык сеанса, локаль (`/VL`) |

## Обновление конфигурации БД

Есть у команд, которые после загрузки обновляют конфигурацию базы данных: `cf load`, `cfe load`, `cf vendor-update`, `infobase update`. Действуют только при работе через Конфигуратор; `ibcmd` выполняет `config apply` без этих ключей.

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--rtype` | - | Режим реструктуризации: `v1` (обычный) или `v2` (оптимизированный) |
| `--dynamic` | - | Разрешить динамическое обновление (`-Dynamic+`); без флага - `-Dynamic-` |

## Формат исходников

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--src-format` | - | Формат каталога исходников: `auto` (по умолчанию), `edt`, `xml` |

При `auto` формат определяется по маркерам каталога: для ввода - что лежит в каталоге, для вывода - формат существующего целевого каталога (несуществующий или пустой - XML). Вместе с набором подключаются опции `--edt-*`. Подробнее: [Исходники в формате 1С:EDT](./edt).

## Запуск клиента

Есть у `run enterprise` и `test *`.

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--ordinaryapp` | `VRUNNER_ORDINARYAPP` | Клиент: `1` - толстый (`/RunModeOrdinaryApplication`), `0` - тонкий, `-1` - авто. По умолчанию и при `-1` - тонкий |
| `--additional` | `VRUNNER_ADDITIONAL` | Дополнительные параметры командной строки 1С:Предприятия |
| `--ibsrv` | `VRUNNER_IBSRV` | Запустить клиент через автономный сервер `ibsrv` (только файловые ИБ; с `--no-wait` игнорируется) |
| `--ibsrv-direct` | `VRUNNER_IBSRV_DIRECT` | Подключаться к `ibsrv` прямым соединением (`/S`) вместо веб-сервиса (`/WS`) |
| `--ibsrv-debug` | `VRUNNER_IBSRV_DEBUG` | Включить порт отладки на запущенном `ibsrv` |
| `--ibsrv-attach` | `VRUNNER_IBSRV_ATTACH` | Не запускать свой `ibsrv`, а подключиться к уже работающему на `localhost:<--ibsrv-port>`; по завершении сервер не останавливается |
| `--ibsrv-port` | `VRUNNER_IBSRV_PORT` | Порт `ibsrv`: при `--ibsrv-attach` - порт подключения (обязателен), иначе - порт запуска (занят - ошибка). Без опции порт подбирается автоматически |

## Кластер серверов

Есть у команд `cluster *`, которые адресуют базу не строкой подключения, а именем в кластере.

| Опция | Переменная окружения | Описание |
|-------|---------------------|----------|
| `--ras` | `VRUNNER_RAS` | Адрес сервера администрирования RAS (по умолчанию `localhost:1545`) |
| `--rac` | `VRUNNER_RAC` | Путь к утилите `rac` |
| `--db-name` | `VRUNNER_IBNAME` | Имя информационной базы в кластере |
| `--cluster` | - | Идентификатор кластера |
| `--cluster-name` | - | Имя кластера |
| `--cluster-admin` | `VRUNNER_CLUSTERADMIN_USER` | Администратор кластера |
| `--cluster-pwd` | `VRUNNER_CLUSTERADMIN_PWD` | Пароль администратора кластера |
| `--db-user` | `VRUNNER_DBUSER` | Пользователь информационной базы |
| `--db-pwd` | `VRUNNER_DBPWD` | Пароль пользователя ИБ |

Если ни `--cluster`, ни `--cluster-name` не заданы, берётся первый кластер сервера.

## Примеры

```bash
# Файловая ИБ через Конфигуратор
vrunner cf load --ibconnection /F./ib --db-user Admin --db-pwd secret ./src

# Серверная ИБ через ibcmd: нужны опции СУБД
vrunner cf load \
  --ibcmd \
  --ibconnection "/SMyServer\MyIB" \
  --dbms-type PostgreSQL \
  --dbms-server db.example.com \
  --dbms-base my_db \
  --dbms-user postgres \
  --dbms-pwd db_password \
  ./src

# Без базы: сборка cf во временной ИБ
vrunner cf compile --ibcmd -s ./src ./build/App.cf

# Тесты толстым клиентом через ibsrv
vrunner test xunit --ibconnection /F./ib --ordinaryapp 1 --ibsrv ./tests
```
