# Интеграция с ИИ-ассистентами (MCP)

vanessa-runner умеет работать как [MCP](https://modelcontextprotocol.io/)-сервер
(Model Context Protocol) — выставлять свои команды как **инструменты для
ИИ-ассистентов**. После подключения ассистент (Claude, Copilot, Cursor и др.)
может сам собирать конфигурации, запускать тесты, обслуживать информационные базы —
вызывая vrunner за вас.

Сервер запускается командой:

```bash
vrunner mcp
```

Работает по протоколу stdio: его запускает и общается с ним сама IDE/клиент,
вручную эту команду выполнять не нужно — достаточно прописать её в конфигурации
подключения (см. ниже).

## Что это даёт

- ассистент видит список команд vrunner с описанием и параметрами и подставляет
  аргументы сам;
- вывод выполняемой команды передаётся ассистенту **по мере выполнения** — видно
  ход сборки/тестов в реальном времени;
- команды, изменяющие информационную базу, хранилище или кластер, помечены как
  разрушающие — клиент запросит у вас подтверждение перед запуском;
- источник один и тот же — это обычные команды vrunner, поэтому поведение
  совпадает с ручным запуском в терминале.

## Требования

- установленный vanessa-runner (`opm install vanessa-runner`), команда `vrunner`
  доступна в `PATH`;
- установленная платформа 1С:Предприятие (как и для обычной работы vrunner).

Если `vrunner` не установлен в `PATH`, сервер можно запускать из исходников через
`oscript src/main.os mcp` (см. варианты ниже).

## Подключение в IDE

Во всех клиентах принцип один: добавить MCP-сервер с командой запуска `vrunner mcp`.
Отличается только файл и формат конфигурации.

::: code-group

```json [Claude Code (.mcp.json)]
{
  "mcpServers": {
    "vrunner": {
      "command": "vrunner",
      "args": ["mcp"]
    }
  }
}
```

```json [Cursor (.cursor/mcp.json)]
{
  "mcpServers": {
    "vrunner": {
      "command": "vrunner",
      "args": ["mcp"]
    }
  }
}
```

```json [VS Code (.vscode/mcp.json)]
{
  "servers": {
    "vrunner": {
      "type": "stdio",
      "command": "vrunner",
      "args": ["mcp"]
    }
  }
}
```

```json [Windsurf (mcp_config.json)]
{
  "mcpServers": {
    "vrunner": {
      "command": "vrunner",
      "args": ["mcp"]
    }
  }
}
```

```json [Claude Desktop (claude_desktop_config.json)]
{
  "mcpServers": {
    "vrunner": {
      "command": "vrunner",
      "args": ["mcp"]
    }
  }
}
```

:::

- **Claude Code** — файл `.mcp.json` в корне проекта (общий для команды), либо
  команда `claude mcp add vrunner -- vrunner mcp`.
- **Cursor** — `.cursor/mcp.json` в проекте или `~/.cursor/mcp.json` глобально.
- **VS Code** — `.vscode/mcp.json` в проекте (обратите внимание: ключ `servers`
  и поле `type`, в отличие от остальных клиентов).
- **Windsurf** — раздел «MCP Servers» в настройках Cascade или файл
  `~/.codeium/windsurf/mcp_config.json`.
- **Claude Desktop** — `claude_desktop_config.json` (в меню *Settings → Developer*).

### Запуск из исходников (без установки в PATH)

Если работаете с vanessa-runner из репозитория, укажите `oscript` и путь к точке
входа. Рабочим каталогом должен быть корень проекта:

```json
{
  "mcpServers": {
    "vrunner": {
      "command": "oscript",
      "args": ["src/main.os", "mcp"]
    }
  }
}
```

## Проверка подключения

После добавления конфигурации перезапустите IDE/клиент (или переподключите
сервер). В списке доступных инструментов появятся команды с префиксом `vrunner`,
например `cf_compile`, `test_xunit`, `infobase_init`.

Попросите ассистента, например: «собери конфигурацию из `src` в `build/1cv8.cf`» —
он подберёт инструмент `cf_compile` и подставит параметры.

## Безопасность

Сервер только выставляет команды — никаких новых прав он не даёт. Разрушающие
операции (загрузка в ИБ, операции с хранилищем и кластером) клиент по умолчанию
запрашивает у вас перед выполнением. Интерактивные команды (`run designer`,
`run enterprise`) в MCP не выставляются.
