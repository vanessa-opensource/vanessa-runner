# Юнит-тесты vanessa-runner

## Куда класть и как запускать

`tests/unit/<Пакет>/Тест<Класс>.os`, пакет = каталог класса в `src/core` (`Сервисы`, `Движки`, `Файлы`, ...).
Один файл на класс. Хелперы - в `tests/unit/utils` (`Классы/` и `Модули/`), тесту достаточно `#Использовать "../utils"`.

Полный прогон из корня: `oscript tasks/test_unit.os` (отчёт `build/reports/junit-unit.xml`).
Один файл: `oneunit execute -f tests/unit/<Пакет>/<Файл>.os`. Библиотеки берутся из `oscript_modules`
(`opm install -l`); если oneunit их не видит - см. `.github/instructions/tests.instructions.md`.

## Тест за 5 минут

```bsl
// BSLLS-off
// Юнит-тесты <Класс>: <что покрыто одной строкой>. Внешние вызовы (<что>) замоканы.

#Использовать asserts
#Использовать moskito
#Использовать tempfiles
#Использовать "../utils"

Перем Стенд;
Перем Сервис;
Перем Любое;

&ПередКаждым
Процедура ПередКаждым() Экспорт
	Стенд = Новый Стенд;
	Стенд.Реальный("<Зависимость>"); // только то, что должно быть настоящим (см. «Что мок делает по умолчанию»)
	Сервис = Стенд.Сервис("<Класс>");
	Любое = Матчеры.ЛюбоеЗначение();
КонецПроцедуры

&ПослеКаждого
Процедура ПослеКаждого() Экспорт
	ВременныеФайлы.Удалить(); // если тест создаёт файлы (ТестовыеФайлы, ВременныеФайлы, пресет временной базы)
КонецПроцедуры

#Область <МетодSUT>

&Тест
Процедура ТестДолжен_<Результат>_<Условие>() Экспорт

	// Дано - поведение зависимостей, отличное от умолчаний
	Стенд.Мок("<Зависимость>").Когда().<Метод>(Любое).ТогдаВозвращает(<Значение>);

	// Когда
	Сервис.<МетодSUT>(...);

	// Тогда - вызовы зависимостей и результат
	Стенд.Мок("<Зависимость>").ПроверитьЧтоВызывалсяМетод().<Метод>(<Аргументы>);
	Стенд.ПроверитьЧтоНеВызывался("<Зависимость>", "<Метод>");

КонецПроцедуры

#КонецОбласти
```

Живой пример - `tests/unit/Сервисы/ТестСервисРасширений.os` (`ТестДолжен_ЗафиксироватьИнкремент_ПослеЗагрузкиРасширенияИзФайлов`).
Одна `#Область` на публичный метод SUT (или группу родственных методов) в порядке объявления. Исключение - одной строкой:

```bsl
Ожидаем.Что(Сервис).Метод("ЗагрузитьРасширениеВБазу", ТестовыеДанные.Массив(База, "нет/МоёРасш.cfe"))
	.ВыбрасываетИсключение("Файл расширения не найден");
```

Два фрагмента одного исключения - цепочкой `.ВыбрасываетИсключение(A).ВыбрасываетИсключение(B)` (метод вызывается дважды).
Если после исключения проверяется побочный эффект - `Ожидаем.Метод(...)` и затем проверка эффекта (см. `ТестСервисСервераОтладки`).

Классы без `&Желудь` (конвертеры, разборы, `ЛокальныйСервер`) - просто `Новый Класс(...)`, стенд не нужен;
тогда пакет подключается явно: `#Использовать "../../../src/core/<Пакет>"` (типы регистрирует Стенд, а он не загружен).
Хуки называются `ПередКаждым` / `ПослеКаждого`.

## Стенд - три фразы

`Сервис("X")` - тестируемый объект; `Мок("Имя")` - его зависимость-мок; `Реальный("Имя")` /
`Подменить("_поле", Значение)` - настоящая зависимость или значение любого поля.

| Метод | Что делает |
|---|---|
| `Сервис(ИмяКласса, ПараметрыКонструктора = Неопределено)` | Реальный экземпляр: `&Лог` -> logos `vrunner`, каждое `&Пластилин`-поле -> мок (или то, что уже объявлено `Реальный`/`Подменить`), `Тип = "Соответствие"` -> соответствие моков по прозвищу. Повторный вызов - тот же объект. |
| `Реальный(ИмяКласса, ПараметрыКонструктора = Неопределено)` | То же, но для зависимости. Подставляется во все уже собранные объекты стенда с полем такого имени. Её зависимости - моки того же стенда. |
| `Мок(ИмяТипа)` | Мок moskito по имени типа (src/core или внешняя библиотека) с поведением по умолчанию. Это тот же экземпляр, что внедрён в собранные объекты. Для типа, объявленного реальным или подменённого, - исключение. |
| `Подменить(ИмяПоля, Значение)` | Значение поля во всех объектах стенда, собранных и будущих: `_Фабрика*`, `_Запущен`, `Поделка`, любой фейк. Возвращает `Значение`. |
| `Вызовы(ИмяТипа, ИмяМетода)` | Массив структур «имя параметра -> значение» по каждому вызову мока (все параметры сигнатуры, включая умолчания): `Вызовы("СервисЗапускаОбработок", "ВыполнитьОбработку")[0].Параметры`. Несуществующий метод - исключение. |
| `ПроверитьЧтоНеВызывался(ИмяТипа, ИмяМетода)` | Утверждение, что метод мока не вызывался. |

Порядок объявления не важен: `Реальный`/`Подменить` после `Сервис` подставляются в уже собранный объект.
`Реальный(X)`/`Подменить(X)` после `Мок(X)` заменяют мок во всех объектах стенда; полученная раньше ссылка
на мок никуда не внедрена - не держите её; `Мок(X)` после этого - исключение. Имена - без учёта регистра.

## Что мок делает по умолчанию

Функции возвращают `NULL`, процедуры ничего не делают, вызовы записываются. Настройка - `Когда().Метод(...)`
с `ТогдаВозвращает(Значение)` (только для функций), `ТогдаВыбрасываетИсключение("текст")`, `ТогдаОтвечает(Ответ)`.
Аргументы в `Когда()` и `ПроверитьЧтоВызывалсяМетод()` сравниваются все: неуказанные хвостовые - это умолчания
сигнатуры, а не «любое» (`ПроверитьЧтоВызывалсяМетод().Метод("a")` не совпадёт с вызовом `Метод("a", "b")`).

Пресеты из `utils/Модули/ПоведениеМоков.os` (править вместе с этой таблицей):

| Тип | Пресет |
|---|---|
| `УправлениеКонфигуратором` | `ПолучитьПараметрыЗапуска()` -> свежая копия `["DESIGNER", "/IBConnectionString""File=stub""", "/Out ""default-out"""]`; `ВыводКоманды()` -> `""`; `ПутьКПлатформе1С()` -> `"1cv8.exe"`; `ПутьКТонкомуКлиенту1С()` -> `"1cv8c.exe"` |
| `УправлениеИБ` | `ОписанияРасширений()` -> пустой массив |
| `СервисОкружения` | шпион над реальным объектом: `НайтиВPATH(Любое)` -> `""`, `КаталогVanessaADD()` -> `""`, остальное настоящее |
| `ДвижокКонфигуратор`, `ДвижокIbcmd` | `СоздатьВременнуюБазу(Любое)` -> новый временный каталог на каждый вызов (`ТестовыеДанные.ВременнаяФайловая()`) |
| `СервисЗапускаОбработок` | `ВыполнитьОбработку(Любое x5)` -> `ТестовыеДанные.РезультатОбработки()` |
| `СервисEDT` | `ПодготовитьXML(Любое, Любое)` -> `ТестовыеДанные.КонтекстXML(<путь источника>)`; `НачатьВыгрузку(Любое, Любое)` -> `ТестовыеДанные.КонтекстВыгрузки(<целевой каталог>)` - исходники как есть, без EDT |

Особенность moskito: `Когда()` в тесте на метод с пресетом заменяет пресет целиком, даже если
параметры конкретнее (`Когда().М("a", Любое)` после пресета `Когда().М(Любое, Любое)`).

Если SUT ждёт от зависимости Структуру/Массив/Булево - объявляйте `Реальный` либо стабьте
`Когда()...ТогдаВозвращает(ТестовыеДанные.<Структура>)`. Типовые решения: `СервисВременнойБазы` -> `Реальный`;
`ФайловыеОперации`, `СервисПоискаИсточников` -> `Реальный`, если тест трогает файловую систему;
`СервисРасчетаИнкремента.Рассчитать*` -> `ТестовыеДанные.РезультатИнкремента`. Нужны и настоящие методы
зависимости, и проверка её вызовов - шпион: `Стенд.Подменить("СервисEDT", Мок.Следить(Стенд.Реальный("СервисEDT")))`.

Новый мок внешней библиотеки: `Стенд.Мок("ИмяКласса")` работает сразу. Поведение по умолчанию - ветка в
`ПоведениеМоков.Применить` (правило: одинаковый `Когда()` в 3+ тестах разных файлов); нестандартное создание -
ветка в `Создать`; новая библиотека - `#Использовать` там же.

## Мок или стаб

**Мок** - если нужно только вернуть значение, бросить исключение или проверить вызов.
**Стаб** (класс `*Стаб` в `utils/Классы`) - если нужен эффект: файлы на диске, счётчики попыток, объектный граф
с состоянием. Шапка стаба - 1-2 строки «что имитирует, какое поведение», настройка fluent `С...()`, `Вызовы` -
только если нужны. Подключение к SUT - только `Стенд.Подменить("_поле", Стаб)`; фабрика, отдающая мок, -
`Стенд.Подменить("_ФабрикаКонфигуратора", Новый ФабрикаСтаб(Стенд.Мок("УправлениеКонфигуратором")))`.

## Фикстуры

`ТестовыеФайлы` - файлы и каталоги во временных каталогах tempfiles: `ЗаписатьФайл`, `ПрочитатьФайл`, `ЗаписатьJSON`, `ПрочитатьJSON`,
`Файл(Каталог, "a/b.xml")` (создаёт), `Путь(Каталог, "a/b.xml")` (только путь), `КаталогEDT()`, `КаталогXML()`, `ФайлCfe("Имя")`, `Существует`,
`ЗаписатьПриВызове(ИндексПараметра, Текст)` - `Ответ` для `ТогдаОтвечает`, пишущий файл по пути из параметра мока.
Убирает временные файлы сам тест - `ВременныеФайлы.Удалить()` в `&ПослеКаждого`.

`ТестовыеДанные` - параметры подключения и структуры-результаты: `Файловая("base")`, `ВременнаяФайловая()`,
`Подключение("File=base", "Admin", "secret")`, `ПараметрыИсходников("edt")`, `КонтекстXML`, `КонтекстВыгрузки`,
`РезультатИнкремента`, `РезультатОбработки`, `Массив(Э1, ..., Э8)`.

Пути в тестах относительные (`"base"`, `"src"`); всё, что доходит до диска, - через `ТестовыеФайлы`/`ВременныеФайлы`.

## Нельзя

- Мутировать свойства мока и заводить второй `Стенд` в одном тесте: моки общие на процесс, сбрасывает их стенд.
- Звать `СостояниеМоков` и `Мок.Получить` напрямую - моки только через `Стенд.Мок`.
- Литералы `C:\...`, доходящие до файловой системы (CI гоняет ubuntu и windows).
- Поднимать `Поделка` - только `Стенд.Подменить("Поделка", Новый ПоделкаСтаб)`.

`oscript tasks/test_unit.os` зелёный, число тестов не уменьшилось, BSL Language Server без замечаний
