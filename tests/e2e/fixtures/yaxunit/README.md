# Фикстуры YAxUnit

Каталог содержит данные для тестов команды `vrunner test yaxunit`.

## Состав

- `YAxUnit.cfe` — расширение-движок фреймворка YAxUnit
  (https://github.com/bia-technologies/yaxunit, релиз 25.12), готовый `.cfe`.
  Загружается в ИБ как движок модульного тестирования.
- `tests-ext/` — XML-исходники минимального тестового расширения (имя `test`).
  Содержит общий модуль `Ext1_ПервыйТест` с одним тестом `Сложение`
  (`ЮТест.ОжидаетЧто(2 + 2).Равно(4)`), регистрируемым в `ИсполняемыеСценарии`.
- `yaxunit.json` — пример готового конфигурационного файла запуска YAxUnit
  (передаётся через `--yaxunit-config`). Используется как образец и в негативных
  проверках разрешения путей.

## Интеграционный прогон (тег `integration`)

Лёгкие e2e-тесты (`ТестTestYaxunit.os`: справка, валидация конфига) запускаются
без платформы 1С. Полноценный прогон (тест `ТестДолжен_ПрогнатьТестЧерезYaxunit`,
тег `integration`) дополнительно требует **платформу 1С:Предприятие** и
самодостаточен — обе фикстуры (`YAxUnit.cfe` + `tests-ext/`) лежат рядом, скачивать
ничего не нужно. Сценарий теста:

1. Создаётся пустая файловая ИБ (из `fixtures/empty-ib`).
2. В ИБ загружается движок: `vrunner cfe load --extension-name YAxUnit YAxUnit.cfe`
   (через конфигуратор: обновление БД по умолчанию; безопасный режим и защита от опасных
   действий у расширения выключены — движку нужно читать конфигурационный файл запуска).
3. В ИБ загружается тестовое расширение:
   `vrunner cfe load --extension-name test tests-ext/` (обновление БД к базе выполняется
   по умолчанию — иначе, при `--no-update-db`, модуль расширения не попадёт в метаданные
   сеанса и YAxUnit его не увидит).
4. Запускаются тесты:

   ```
   vrunner test yaxunit --ibconnection "/F<путь к ИБ>" \
       --ext test --report <junit.xml> --exitcode <exit.txt>
   ```

Тест проверяет, что движок реально исполнил `Сложение` (отчёт jUnit содержит
пройденный `testcase`) и что `exitCode` равен `0`.
