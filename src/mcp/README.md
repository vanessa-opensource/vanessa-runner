# MCP-мост для vrunner (ПРОТОТИП)

Выставляет команды vrunner как инструменты MCP (Model Context Protocol) по stdio.
**Единый источник истины** — обычная CLI-команда: помечаешь подкоманду маркером
`&ДоступноВMCP`, и она автоматически появляется как MCP-инструмент. Схема
параметров генерируется рефлексией из аннотаций `&Опция/&Аргумент/&НаборОпций`
(тип, enum, required) — дублировать ничего не нужно.

## Как добавить команду в MCP

```bsl
&ПодкомандаПриложения(Имя = "xunit", Родитель = "КомандаTest", Описание = "...")
&ДоступноВMCP
Процедура ПриСозданииОбъекта()
КонецПроцедуры
```

Всё. Команда работает и в CLI (`vrunner test xunit ...`), и как MCP-инструмент `test_xunit`.

Дополнительные маркеры рядом с `&ДоступноВMCP` задают MCP-аннотации инструмента
(hints для клиента — он по ним решает, спросить подтверждение или автозапустить):

```bsl
&MCPТолькоЧтение                  // readOnlyHint    — экспорт/проверка, ИБ не меняет
&MCPРазрушающая                   // destructiveHint — меняет ИБ/хранилище/кластер
&MCPИдемпотентная                 // idempotentHint  — повтор с теми же аргументами безопасен
&MCPВнешнийМир                    // openWorldHint   — ходит к хранилищу/кластеру/серверной ИБ
&MCPЗаголовок("Дружелюбное имя")  // title           — по умолчанию = Описание команды
```

В `tools/list` каждого инструмента уходит `annotations` с `title` и hints. Маркеры
независимы — вешаются в любом сочетании. `openWorldHint` выводится всегда: по
умолчанию `false` (vrunner работает с локальной ИБ/файлами), `&MCPВнешнийМир`
делает его `true`. Само подтверждение рисует клиент (Claude Code), сервер лишь
объявляет hints.

## Запуск / подключение

```jsonc
// mcp.json (Claude Code / Cursor / расширение IDE)
{ "mcpServers": {
    "vrunner": { "command": "vrunner", "args": ["mcp"] }
    // без установки в PATH:
    // "vrunner": { "command": "oscript", "args": ["src/main.os", "mcp"] }
}}
```

Проверка вручную:
```sh
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | oscript src/main.os mcp
```

## Состав

| Файл | Роль |
|---|---|
| `src/cli/КомандаMCP.os` | команда `vrunner mcp` — точка входа сервера (живёт в cli рядом с остальными командами) |
| `src/mcp/MCP_АннотацияДоступноВMCP.os` | маркер-аннотация `&ДоступноВMCP` (opt-in) |
| `src/mcp/MCP_РеестрИнструментов.os` | рефлексия команд autumn-cli → MCP-инструменты + JSON Schema |
| `src/mcp/MCP_ИнструментНадКомандой.os` | обёртка: исполняет команду как дочерний `vrunner ...` |
| `src/mcp/MCP_СтдиоСервер.os` | минимальный JSON-RPC сервер по stdio |

> `src/mcp` подключается в `src/main.os` через `#Использовать "./mcp"` (до `./cli`,
> чтобы аннотация `&ДоступноВMCP` была зарегистрирована к сканированию команд).

## Архитектурные решения

* **Подкоманда, а не отдельный entrypoint.** Иначе две `&Рогатка` (autumn-cli и
  autumn-mcp) конфликтуют — обе вешают `ПриЗапускеПриложения` + `ЗавершитьРаботу`.
  Команда `mcp` едет на штатной CLI-рогатке, конфликта нет.
* **Сервер вендорён, не зависимость autumn-mcp.** Если повесить autumn-mcp в
  packagedef, его рогатка перехватит КАЖДЫЙ запуск vrunner. Формы JSON-RPC взяты
  из autumn-mcp. Когда в autumn-mcp появится «библиотечный режим» (сервер без
  авто-рогатки) — заменить вендор на зависимость.
* **Исполнение вне процесса.** Инструмент запускает дочерний `vrunner <команда>`
  и перехватывает его вывод. Причины: stdout сервера занят JSON-RPC; команда
  может звать `ЗавершитьРаботу`; переиспользуется ровно CLI-путь.
