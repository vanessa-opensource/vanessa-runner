# MCP-мост для vrunner

Выставляет команды vrunner как инструменты MCP (Model Context Protocol) по stdio.
**Единый источник истины** — обычная CLI-команда: помечаешь подкоманду маркером
`&ДоступноВMCP`, и она автоматически появляется как MCP-инструмент. Схема
параметров генерируется рефлексией из аннотаций `&Опция/&Аргумент/&НаборОпций`
(тип, enum, required) — дублировать ничего не нужно.

## Архитектура

Сервер — **отдельная точка входа** `src/mcp.os` (не подкоманда `vrunner mcp`):
так рогатки `autumn-cli` и `autumn-mcp` не конфликтуют. Сервер строится на
библиотеке [`autumn-mcp`](https://github.com/autumn-library), команды исполняются
**in-process**:

- бин команды резолвится из autumn-контейнера (`Поделка.НайтиЖелудь`), сервисы
  `&Пластилин` автовайрятся;
- наборы опций (`&НаборОпций`) — синглтоны контейнера, несут настройки сессии;
- поля заполняются Рефлектором из аргументов инструмента, затем
  `Команда.ВыполнитьДействие()`.

Дочерний процесс на синхронный вызов не запускается. Лог команды (логгер
`vrunner.*`) стримится клиенту как `notifications/message` через
`MCP_АппендерУведомлений`.

## Как добавить команду в MCP

```bsl
&ПодкомандаПриложения(Имя = "xunit", Родитель = "КомандаTest", Описание = "...")
&ДоступноВMCP
Процедура ПриСозданииОбъекта()
КонецПроцедуры
```

Всё. Команда работает и в CLI (`vrunner test xunit ...`), и как MCP-инструмент `test_xunit`.

### Маркеры намерения

Рядом с `&ДоступноВMCP` можно задать маркеры — подсказки о характере команды:

```bsl
&MCPДлительная                    // команда долгая → по умолчанию исполняется в фоне (taskId)
&MCPТолькоЧтение                  // readOnlyHint    — экспорт/проверка, ИБ не меняет
&MCPРазрушающая                   // destructiveHint — меняет ИБ/хранилище/кластер
&MCPИдемпотентная                 // idempotentHint  — повтор с теми же аргументами безопасен
&MCPВнешнийМир                    // openWorldHint   — ходит к хранилищу/кластеру/серверной ИБ
&MCPЗаголовок("Дружелюбное имя")  // title           — по умолчанию = Описание команды
```

`&MCPДлительная` **функциональна** — управляет фоновым исполнением (см. ниже).
Остальные маркеры (`&MCPРазрушающая` и пр.) фиксируют намерение в коде; текущий
сервер `autumn-mcp` не транслирует их в поле `annotations` ответа `tools/list`,
поэтому hint-подтверждения на стороне клиента пока не строятся. Маркеры сохранены
как дешёвая разметка на будущее.

## Экономия токенов: наборы опций → инструменты `set_*`

Общие наборы опций (подключение, платформа, СУБД, настройки и пр.) **не** попадают
в схему каждой команды — иначе ~18 опций дублировались бы в каждом из ~49
инструментов. Вместо этого на каждый набор генерируется инструмент `set_*`
(`set_connection`, `set_platform`, `set_dbms`, …): он пишет значения в
бин-синглтон набора. Команды берут тот же синглтон, поэтому опция задаётся
**один раз за сессию** и действует, пока не изменена.

```
set_platform { "v8version": "8.3.24" }   // один раз
cf_compile   { "OUT": "build/1cv8.cf", "src": "src" }   // подхватит платформу из сессии
```

## Длительные команды: фон и поллинг

Команды с `&MCPДлительная` (тесты, `init/update`, сборка cf) по умолчанию
исполняются **фоном**, чтобы не блокировать stdio-цикл сервера: запускается
отдельный процесс `oscript src/main.os <подкоманда> <флаги>`, вывод пишется в файл,
а инструмент сразу возвращает `taskId`. Сессионные наборы опций реконструируются
в CLI-флаги — дочерний процесс самодостаточен.

Управление задачей:

| Инструмент | Назначение |
|---|---|
| `task_status` | состояние по `taskId`: `running` / `completed` / `failed` (+ код возврата) |
| `task_result` | результат и лог (доступен и пока задача выполняется) |
| `task_cancel` | отменить (завершает дерево процессов) |

Параметр `background` (есть в схеме длительных команд) переопределяет режим:
`background: false` — выполнить синхронно с потоковым логом.

## Отладочный лог: параметр `debug`

У каждой команды в схеме есть `debug`. При `debug: true`:

- команда выполняется **синхронно** (длительную тоже переводит в синхрон);
- на время вызова уровень логгеров `vrunner*` поднимается до Отладки, лог
  захватывается отдельным буфер-аппендером (`MCP_БуферАппендер`) и **возвращается
  в результате** инструмента;
- уровень и аппендер всегда восстанавливаются (в т.ч. при исключении);
- отладка идёт только в результат — клиентский стрим и фреймворковый шум не
  затрагиваются.

## Запуск / подключение

```jsonc
// .mcp.json (Claude Code / Cursor / расширение IDE)
{ "mcpServers": {
    "vrunner": { "command": "vrunner-mcp" }
    // из исходников, рабочий каталог — корень проекта:
    // "vrunner": { "command": "oscript", "args": ["src/mcp.os"] }
}}
```

Проверка вручную:
```sh
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | oscript src/mcp.os
```

## Состав

| Файл | Роль |
|---|---|
| `src/mcp.os` | точка входа сервера (stdio) |
| `src/mcp/Классы/MCP_Запуск.os` | сборка контекста и запуск сервера autumn-mcp |
| `src/mcp/Классы/MCP_РеестрИнструментов.os` | рефлексия команд autumn-cli → MCP-инструменты + JSON Schema |
| `src/mcp/Классы/MCP_ИнструментКоманды.os` | исполнение команды in-process: синхронно / фоном / с debug |
| `src/mcp/Классы/MCP_ИнструментНастройкиОпций.os` | инструменты `set_*` (сессионные наборы опций) |
| `src/mcp/Классы/MCP_РеестрЗадач.os` | реестр фоновых задач: запуск процесса, статус, лог, отмена |
| `src/mcp/Классы/MCP_ИнструментЗадачи.os` | инструменты `task_status` / `task_result` / `task_cancel` |
| `src/mcp/Классы/MCP_АппендерУведомлений.os` | аппендер logos → `notifications/message` (стриминг лога) |
| `src/mcp/Классы/MCP_БуферАппендер.os` | буфер-аппендер logos для захвата debug-лога |
| `src/mcp/Классы/MCP_АннотацияДоступноВMCP.os` | маркер `&ДоступноВMCP` (opt-in) |
| `src/mcp/Классы/MCP_Аннотация*.os` | маркеры намерения (`&MCPДлительная`, `&MCPРазрушающая` и пр.) |

> `src/mcp.os` загружает `autumn-cli` (команды как желуди для рефлексии) и
> `autumn-mcp` (сервер); вся логика сборки/запуска — в `MCP_Запуск`.
